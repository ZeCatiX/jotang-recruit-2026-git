## Q1：卷积层和全连接层有什么区别？

**答：** 核心区别在于**参数共享（weight sharing）**和**空间关系保持**。

| 维度 | 全连接层 | 卷积层 |
|------|---------|--------|
| 参数 | 每个输出神经元连每个输入神经元，参数量 = 输入数 × 输出数 | 一个卷积核在整张特征图上滑动，**所有位置共享同一组权重** |
| 参数规模 | 输入 64×64×3 = 12288 维，输出 64 维 → **786,528** 个参数 | 3×3×3 = **27** 个参数（+3 个偏置） |
| 空间关系 | 输入被展平，位置信息丢失 | 保留空间拓扑结构，每个输出对应输入的局部感受野 |
| 计算方式 | 矩阵乘法 `y = Wx + b` | 滑动窗口求和 `y_i = Σ W_k · x_{i+k} + b` |

**实验验证（`code/conv_practice.py`）：**

手写卷积函数 `conv2d_valid` 实现了 3×3 卷积核在 960×540 图片上的滑动，仅用 9 个参数（均值模糊）就能完成模糊效果。如果用全连接层做同样的事，需要 960×540×1 = 518,400 个参数。

```python
# 手写卷积：滑动窗口 + 逐元素相乘 + 求和
def conv2d_valid(image, kernel):
    kh, kw, _ = kernel.shape
    out_h = image.shape[0] - kh + 1
    out_w = image.shape[1] - kw + 1
    for i in range(out_h):
        for j in range(out_w):
            patch = image[i:i+kh, j:j+kw]      # 取 3×3 窗口
            out[i, j] = np.sum(patch * kernel)   # 逐元素相乘再求和
```

**Tensor 形状追踪（`code/cnn_train.py` → `print_model_shapes`）：**

```
输入:          (1, 3, 64, 64)     # 1张3通道图
Conv2d 3→32:   (1, 32, 64, 64)   # 32个通道，空间尺寸不变(padding=1)
BN+ReLU:       (1, 32, 64, 64)   # 归一化+激活，形状不变
MaxPool 2:     (1, 32, 32, 32)   # 高宽各减半
...
Flatten:       (1, 8192)          # 展平后才是全连接层的输入
Linear 8192→256: (1, 256)
```

如果第一步就用全连接层：`Linear(12288, 256)` 就有 **3,145,728** 参数，而整个 CNN 的卷积部分只有 **15,488** 参数。

## Q2：输入输出通道数、padding、stride 对输出尺寸的影响

**答：** 输出尺寸公式为：

$$O = \left\lfloor \frac{H - K + 2P}{S} \right\rfloor + 1$$

其中 H 为输入高度，K 为卷积核大小，P 为 padding，S 为 stride。

**实验验证（`code/conv_practice.py` Part 3）：**

```python
# 输入 5×5，kernel 3×3
# valid (P=0, S=1): O = (5-3)/1 + 1 = 3 → 输出 3×3
# same  (P=1, S=1): O = (5-3+2)/1 + 1 = 5 → 输出 5×5
# valid + stride 2: O = (5-3)/2 + 1 = 2 → 输出 2×2
```

**三种模式的对比图（`figures/fig03_padding对比.png`）：**

| 模式 | 参数 | 输出尺寸 | 特点 |
|------|------|---------|------|
| valid | P=0, S=1 | (H-K+1)×(W-K+1) | 不填充，边缘信息丢失 |
| same | P=K//2, S=1 | H×W | 零填充，保持尺寸不变 |
| stride | P=0, S=2 | (H-K+1)/2+1 | 步长2，高宽减半 |

**通道数变化（`code/cnn_train.py`）：**

```
Conv2d(in=3, out=32)   → 输出 32 个通道（32个卷积核）
Conv2d(in=32, out=64)  → 输出 64 个通道（每个核有 32×3×3=288 参数）
Conv2d(in=64, out=128) → 输出 128 个通道
MaxPool                → 通道数不变，只改变 H×W
```

通道数由**卷积核的数量**决定，与输入通道数无关。

## Q3：为什么特征图的高宽变小、通道增多？

**答：** 这是 CNN **逐步抽象**的设计逻辑。

| 变化 | 原因 | 意义 |
|------|------|------|
| 高宽变小 | MaxPool 每次将 H×W 减半 | 降低计算量，扩大感受野 |
| 通道增多 | Conv 层的 out_channels 逐渐增大 | 提取更多样的特征 |

**具体过程（`code/cnn_train.py` 模型结构）：**

```
Layer              输出形状       感受野增长     参数量
─────────────────────────────────────────────────────────
Input              64 × 64 × 3    1 × 1 = 1       —
Block1 Conv        64 × 64 × 32   3 × 3 = 9       27+32
Block1 Pool        32 × 32 × 32   4 × 4 = 16      —
Block2 Conv        32 × 32 × 64   7 × 7 = 49      2,304+64
Block2 Pool        16 × 16 × 64   8 × 8 = 64      —
Block3 Conv        16 × 16 × 128  15 × 15 = 225   24,704+128
Block3 Pool         8 ×  8 × 128  16 × 16 = 256   —
Flatten           8192 × 1        —              —
```

**特征图可视化（`figures/fig07_特征图可视化.png`）：**

- **Block1（浅层，32通道，64×64）：** 特征图显示的是**边缘和纹理**，像高通滤波器的响应
- **Block3（深层，128通道，8×8）：** 特征图显示的是**物体部件**，如猫眼、狗鼻等语义结构

高宽减小的同时通道增加，使得模型能在更抽象的层面上提取更多样的特征，同时保持计算可控。

## Q4：激活函数、损失函数的选择

### 激活函数：ReLU

**为什么用 ReLU 而不是 Sigmoid/Tanh？**

| 激活函数 | 公式 | 优点 | 缺点 |
|---------|------|------|------|
| Sigmoid | σ(x) = 1/(1+e⁻ˣ) | 输出 (0,1)，有概率解释 | 梯度饱和，训练慢 |
| Tanh | 2σ(2x)-1 | 零中心输出 | 同样有梯度饱和 |
| **ReLU** | **max(0, x)** | **计算快，无梯度饱和，稀疏激活** | 负值区梯度为0（Dead ReLU） |

**实验验证：** 我们的模型使用 `nn.ReLU(inplace=True)`，30 个 epoch 内 loss 从 3.6 降到 0.39，收敛稳定。如果用 Sigmoid，梯度在 |x|>2 时接近 0，训练会慢得多。

**为什么 BN 后接 ReLU？** BatchNorm 将数据标准化到均值为0、方差为1，ReLU 切掉负半部分，两者组合让输出分布更紧凑，后续层更容易学习。

### 损失函数：CrossEntropyLoss

**为什么用交叉熵而不是 MSE？**

| 损失函数 | 适用场景 | 原因 |
|---------|---------|------|
| MSE | 回归 | 误差平方，适合连续值预测 |
| **CrossEntropy** | **分类** | **-log(p)，对置信度错误的惩罚更重** |

对于分类问题，如果模型以 99% 的置信度预测错了，MSE 只看到 0.01 的误差，但 CrossEntropy 会给出 -log(0.01) = 4.6 的巨大惩罚。**梯度更陡峭，收敛更快。**

PyTorch 的 `nn.CrossEntropyLoss` 内部先做 softmax 再做负对数似然，所以模型输出层不需要额外加 softmax。

## Q5：为什么验证集不用数据增强？

**答：** 三个原因：

1. **评估真实性：** 验证集要模拟真实部署场景。真实推理时输入是原始图片，没有增强。如果在验证集上增强，评估结果反映的不是模型在真实数据上的能力。

2. **可比性：** 验证集准确率用于选择最佳 epoch（checkpoint）。如果验证集每次增强不同，同一 epoch 两次跑出的验证准确率不同，无法稳定选模。

3. **不泄露信息：** 验证集的作用是与训练集独立地评估泛化能力。增强会改变分布，破坏独立性。

**我们的预处理策略（`code/cnn_train.py`）：**

```python
# 训练集：增强变换
train_transforms = ComposeTransform([
    RescaleTransform(IMG_SIZE),
    RandomFlipTransform(0.5),       # 随机翻转
    RandomCropTransform(IMG_SIZE, 8),  # 随机裁剪
    NormalizeTransform(),
])

# 验证/测试集：只缩放+归一化，不增强
eval_transforms = ComposeTransform([
    RescaleTransform(IMG_SIZE),
    NormalizeTransform(),
])
```

**实验结果（`results/summary.json`）：**

- 无增强训练：测试准确率 0.696
- 有增强训练：测试准确率 0.652

虽然这次实验中增强没有提升测试准确率（数据集太小，增强可能引入了噪声），但方法论是正确的——增强只作用于训练集。

## Q6：增强变换的合理性

**答：** 数据增强应该基于**对问题合理、对目标不变**的变换。

| 增强方式 | 合理性分析 | 本项目使用 |
|---------|-----------|-----------|
| **随机水平翻转** | 猫/狗左右翻转后还是猫/狗，类别不变 | ✅ 使用（p=0.5） |
| **随机裁剪+平移** | 局部裁剪仍能识别猫/狗，增加鲁棒性 | ✅ 使用（padding=8） |
| 随机垂直翻转 | 如果猫/狗正立和倒立都合理则可用 | ❌ 未使用（倒立的动物不常见） |
| 随机旋转 | 旋转大角度后类别可能变化（倒立的动物） | ❌ 未使用 |
| 随机亮度/对比度 | 光照变化不影响类别，实用性强 | ❌ 未使用（可加入改进） |

**增强效果可视化（`figures/fig08_数据增强.png`）：**

展示了同一张图片在三种变换下的效果：
- **无增强：** 原图缩放后归一化
- **随机水平翻转：** 图片左右镜像
- **随机裁剪+翻转：** 先裁剪再随机翻转，产生不同的视角

**注意：** 增强的前提是变换不改变标签。比如对图片随机裁剪出背景区域，可能让模型难以判断类别——裁剪后仍然需要保留主体。我们的实现使用 `padding=8` 确保裁剪后仍有主体。

## Q7：如何改进模型？（开放题）

基于本项目的实验结果（测试准确率 60.9%，数据量仅 145 张），有以下几个改进方向：

### 1. 增加数据量（最重要）
- 当前 145 张远小于猫狗分类的经典规模（8500 张）
- 可以从 Kaggle Dogs vs Cats 数据集获取完整数据
- 或使用 Hugging Face 的猫狗数据集

### 2. 迁移学习
- 使用 ImageNet 预训练的模型（如 ResNet-18、EfficientNet-B0）
- 冻结特征提取器，只训练分类头
- 在少量数据上也能获得较高准确率

### 3. 改进数据增强
- 加入随机旋转、色彩抖动
- 使用更高级的增强方法（CutMix、MixUp、RandAugment）
- 考虑使用 ALBUMENTATIONS 库

### 4. 学习率调度
```python
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=30)
# 或 ReduceLROnPlateau 基于验证 loss 降低学习率
```

### 5. 模型正则化
- 增大 Dropout 比例（当前 0.3 → 0.5）
- 加入 L2 正则化（weight_decay=1e-4）
- 使用 Early Stopping（验证 loss 不再下降时停止）

### 6. 类别不平衡处理
- 当前 82 猫 vs 63 狗（比例 1.3:1）
- 可使用 ClassWeights 调整损失函数权重
- 或对多数类下采样 / 少数类过采样
