## Q1：前向传播时为什么要保存每一层的输入或输出？反向传播会在哪里用到它们？这和显存有什么关系？

**答：** 前向传播保存中间结果是因为**反向传播需要它们来计算梯度**。

在反向传播中，每个层的梯度计算都依赖于前向传播的中间输出：

| 反向步骤 | 需要的前向中间值 | 用途 |
|---------|----------------|------|
| ∂L/∂z = -(y-p)/N | prob（sigmoid 输出） | 计算 BCE 对 logits 的梯度 |
| ∂L/∂W2 = a.T @ ∂L/∂z | a（ReLU 输出） | 计算第二层权重梯度 |
| ∂L/∂a = ∂L/∂z @ W2.T | W2（第二层权重） | 梯度回传需要 |
| ∂L/∂h = ∂L/∂a * relu'(h) | h（线性层1输出） | ReLU 导数需要 |
| ∂L/∂W1 = X.T @ ∂L/∂h | X（输入） | 计算第一层权重梯度 |

**和显存的关系：**

保存中间结果会消耗显存。对于深层网络：

```
层数 = 100，每层中间结果 = batch_size × hidden_dim × 4 bytes
显存开销 ≈ 层数 × 中间结果大小
```

这就是为什么深度网络训练需要大量显存。有几种优化策略：
- **梯度检查点（gradient checkpointing）：** 丢弃部分中间结果，反向时重新前向计算
- **混合精度训练：** 用 FP16 代替 FP32 存储中间结果，节省 50% 显存

**代码验证（`code/practice2.py`）：**

```python
# 前向保存中间结果
cache = {"h": h, "a": a, "logits": logits, "prob": prob}

# 反向时读取 cache 计算梯度
def backward_numpy(loss, cache, X, y_true, W2):
    h, a, logits, prob = cache["h"], cache["a"], cache["logits"], cache["prob"]
    dL_dz = -(y - prob) / N       # 需要 prob
    dL_dW2 = a.T @ dL_dz          # 需要 a
    dL_dh = dL_da * relu_grad(h)  # 需要 h
```

## Q2：链式法则怎样把损失函数的梯度传回第一层权重？

**答：** 链式法则沿着计算图**从损失反向逐层传递**梯度。

以本项目的两层网络为例（计算图见 `figures/fig03_计算图_神经网络.png`）：

```
L ← p ← z ← (a ← h ← X, W1, b1), (W2, b2)
```

**传递路径（∂L/∂W1）：**

```
∂L/∂W1 = ∂L/∂p · ∂p/∂z · ∂z/∂a · ∂a/∂h · ∂h/∂W1

= ∂L/∂p · σ'(z) · W2.T · relu'(h) · X.T
```

**用代码对应（`code/practice2.py` → `backward_numpy`）：**

```python
# 第②步：∂L/∂logits（从 loss 到 z）
dL_dlogits = -(y_true - prob) / N       # ∂L/∂z = ∂L/∂p · σ'(z) = -(y-p)/N

# 第⑤步：∂L/∂a（从 z 到 a）
dL_da = dL_dlogits @ W2.T               # ∂z/∂a = W2.T

# 第⑥步：∂L/∂h（从 a 到 h）
dL_dh = dL_da * relu_grad(h)            # ∂a/∂h = relu'(h)

# 第⑦步：∂L/∂W1（从 h 到 W1）
dL_dW1 = X.T @ dL_dh                    # ∂h/∂W1 = X.T
```

**关键观察：** 链式法则像"接力赛"，每一层的局部梯度乘起来就是最终梯度。

## Q3：二元交叉熵与 Sigmoid 配合后，loss 对 logit 的梯度是什么？为什么方便反向传播？

**答：** 梯度公式惊人地简洁：

$$\frac{\partial L}{\partial z} = \frac{p - y}{N}$$

**推导过程：**

```
L = -1/N · [y·log(p) + (1-y)·log(1-p)]    # BCE loss
p = σ(z) = 1/(1+e⁻ᶻ)                       # Sigmoid

∂L/∂p = -(y/p - (1-y)/(1-p)) / N          # 对 p 求导

dp/dz = p·(1-p)                            # Sigmoid 导数

∂L/∂z = ∂L/∂p · dp/dz
      = [-(y/p - (1-y)/(1-p)) / N] · p·(1-p)
      = [-((y-p)/(p·(1-p))) / N] · p·(1-p)
      = -(y - p) / N                       # 化简！
```

**为什么方便？**

1. **公式极简：** `-(y - p) / N`，不需要再存 sigmoid 导数或做除法
2. **无梯度消失：** 即使 p 接近 0 或 1，梯度 = 预测误差本身，不会像 tanh 那样饱和到 0
3. **训练稳定：** 梯度大小直接反映预测误差，预测错了梯度大，预测对了梯度小
4. **计算高效：** 只需一次减法、一次除法，无需指数运算

**代码验证（`code/practice2.py`）：**

```python
# Sigmoid + BCE 的简化梯度
dL_dlogits = -(y_true - prob) / N  # 一行搞定，不用分别算 ∂L/∂p 和 dp/dz
```

## Q4：NumPy 梯度与 PyTorch 梯度出现差异时，怎样判断问题出在哪里？

**答：** 建立一个**系统的排查清单**，从常见错误开始逐一排除：

| 排查项 | 检查方法 | 典型错误 |
|-------|---------|---------|
| 1. **公式错误** | 手推链式法则，逐步对比 | 漏乘某个因子、漏做转置 |
| 2. **矩阵转置** | 打印每个中间结果的形状 | `X.T @ dL` 写成 `X @ dL.T` |
| 3. **广播（Broadcast）** | 确认运算维度对齐 | `(1,N)` 和 `(N,)` 混用 |
| 4. **损失归约** | 确认 mean vs sum | BCE 用 mean 但反向忘了除 N |
| 5. **激活函数** | 确认导数公式 | ReLU 导数写成 `(h > 0)` 而非 `relu'(h)` |
| 6. **数值精度** | 对比误差量级 | 1e-7 是浮点误差，1e-3 是逻辑错误 |

**我的排查经验（来自实践 2 的调试过程）：**

**错误 1：矩阵转置**

```python
# 错误：∂L/∂W1 = X @ dL_dh  ← 形状 (1,2) @ (1,4) 不匹配
# 正确：∂L/∂W1 = X.T @ dL_dh  ← 形状 (2,1) @ (1,4) = (2,4) ✓
```

**错误 2：PyTorch 权重形状约定**

```python
# NumPy: W1 是 (input_dim, hidden_dim)
# PyTorch linear: 期望 (out_features, in_features) = (hidden_dim, input_dim)
# 解决：用 matmul(X, W1) 而非 linear(X, W1)，保持形状一致
```

**错误 3：keepdims 导致形状不匹配**

```python
# 错误：dL_db1 = np.sum(dL_dh, axis=0, keepdims=True)  → shape (1,4)
# PyTorch: db1.grad.shape = (4,)                         → shape (4,)
# 解决：去掉 keepdims，或比较时 reshape
```

**错误 4：BCE 归约方式**

```python
# 如果 BCE 用 sum 而非 mean，梯度需要除以 N
# torch.nn.BCELoss() 默认 reduction='mean'，需要对应除以 N
dL_dz = -(y - p) / N  # 除以 batch size
```

**实用技巧：**

```python
# 先检查形状，再检查数值
print(f"dW1 shape: NumPy={np_grads['dW1'].shape}, PyTorch={torch_grads['dW1'].shape}")

# 对比范围而非单个值（容易发现量级错误）
print(f"NumPy range: [{np_grads['dW1'].min():.4f}, {np_grads['dW1'].max():.4f}]")
print(f"PyTorch range: [{torch_grads['dW1'].min():.4f}, {torch_grads['dW1'].max():.4f}]")

# 如果范围完全一致但形状不对 → 转置/广播问题
# 如果形状一致但范围差 10x → 可能是 N 除法或 sum/mean 问题
```

## Q5：完成两次验证后，你现在怎样理解 loss.backward()？

**答：** 经过实践 1（简单计算链）和实践 2（神经网络）的手写反向传播，我对 `loss.backward()` 的理解是：

### 它做了两件事：

**① 保存计算图（前向时自动完成）**

```
X → h → a → z → p → L
  ↑    ↑    ↑    ↑    ↑
  [保存输入] [保存中间结果] [记录运算类型]
```

PyTorch 在前向传播时自动构建了一个有向无环图（DAG），每个操作节点记录了：
- 输入的 tensor（用于反向时计算梯度）
- 操作的类型（matmul、relu、sigmoid、add 等）
- 是否需要梯度（`requires_grad=True`）

**② 执行链式法则（backward 时自动完成）**

```python
loss.backward()
```

这一行代码做了以下事情（按顺序）：
1. 从 loss 节点出发，沿着计算图反向遍历
2. 对每个节点，根据其操作类型调用对应的梯度公式
3. 将梯度累加到 `tensor.grad` 属性中

### 它替我们完成了什么？

| 手工工作 | PyTorch 自动完成 |
|---------|-----------------|
| 构建计算图 | ✅ 前向传播时自动记录 |
| 保存中间结果 | ✅ 每个操作的输入都保留在图中 |
| 链式法则推导 | ✅ 内置梯度公式 |
| 梯度累加 | ✅ 多个路径的梯度自动求和 |
| 广播规则处理 | ✅ 自动处理维度不匹配 |
| 内存管理 | ✅ 自动释放不需要的中间结果 |

### 但它没有做什么？

- **没有保存参数**（参数是你创建的）
- **没有优化参数**（`loss.backward()` 只算梯度，不更新参数）
- **没有选择学习率**（需要优化器如 SGD、Adam）
- **没有检测梯度问题**（梯度消失、爆炸需要你自己监控）

**验证代码（`code/practice1.py`）：**

```python
# PyTorch 前向：自动构建计算图
x = torch.tensor(2.0, requires_grad=True)
a = x * y          # 记录 "multiply" 操作，保存 x, y
b = x ** 2         # 记录 "pow" 操作，保存 x
c = a + b          # 记录 "add" 操作，保存 a, b
f = c ** 2         # 记录 "pow" 操作，保存 c

# PyTorch 反向：自动执行链式法则
f.backward()        # 自动计算 df/dc → dc/da → da/dx, dc/db → db/dx → 累加到 x.grad

# 结果与手写完全一致
print(x.grad)       # 140.0 = 2c(y+2x) = 2*10*(3+4)
```

## Q6：将你遇到的报错或不理解的点记录

### 报错 1：PyTorch linear 层权重形状不匹配

```
RuntimeError: mat1 and mat2 shapes cannot be multiplied (1x2 and 4x2)
```

**原因：** NumPy 中 W1 形状为 (input_dim, hidden_dim)，但 `torch.nn.functional.linear` 期望 (out_features, in_features)。

**解决：** 用 `torch.matmul(X, W1)` 代替 `torch.nn.functional.linear(X, W1, b1)`，保持与 NumPy 相同的形状约定。

### 报错 2：NumPy keepdims 导致形状不匹配

```
db1: 形状不匹配! NumPy=(1, 4) vs PyTorch=(4,)
```

**原因：** `np.sum(..., axis=0, keepdims=True)` 返回 (1, 4)，而 PyTorch 的 `.grad` 是 (4,)。

**解决：** 去掉 `keepdims=True`，或比较时 `reshape` 统一形状。

### 报错 3：backward_numpy 缺少参数

```
NameError: name 'W2' is not defined
```

**原因：** 反向传播需要 W2 来计算 `∂L/∂a = ∂L/∂z @ W2.T`，但函数签名没传 W2。

**解决：** 在函数签名中添加 W2 参数。

### 不理解的点 1：为什么单样本和 batch 的参数梯度形状一样？

**困惑：** 我以为 batch 变大后梯度形状也会变。

**理解：** 参数 W1、b1、W2、b2 的形状由网络结构决定，与 batch size 无关。Batch size 只影响中间结果的维度（第一维从 1 变成 N），但梯度通过 `@` 运算自动"汇总"了 batch 的信息：

```
∂L/∂W1 = X.T @ dL_dh
        (N, d).T @ (N, h) = (d, N) @ (N, h) = (d, h)  ← batch 被矩阵乘法"消掉"了
```

### 不理解的点 2：Sigmoid+BCE 为什么能化简？

**困惑：** 两个复杂公式相乘后竟然变成 `-(y-p)/N`，直觉上说不通。

**理解：** Sigmoid 的导数 `p(1-p)` 恰好抵消了 BCE 导数中的 `1/(p(1-p))` 项：

```
∂L/∂p = -(y/p - (1-y)/(1-p)) / N = -((y-p)/(p(1-p))) / N
dp/dz = p(1-p)

∂L/∂z = ∂L/∂p · dp/dz = -((y-p)/(p(1-p))) / N · p(1-p) = -(y-p)/N
```

这个巧合让反向传播变得极其简洁——**梯度就是预测误差**，这也是为什么 Sigmoid+BCE 是二分类的标准搭配。

### 不理解的点 3：为什么 ReLU 的梯度是 `(h > 0)` 而不是 `(h > 0).astype(float)`？

**困惑：** 代码里用了 `astype(float)`，但布尔值乘法似乎也能工作。

**理解：** `relu_grad(h) = (h > 0)` 返回布尔数组，与浮点数组相乘时 NumPy 会自动转换（True→1, False→0）。显式用 `astype(float)` 更清晰，但两种写法结果相同。
