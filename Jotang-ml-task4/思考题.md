## Q1：为什么 Scaled Dot-Product Attention 要除以 √d_k？

**答：** 除以 √d_k 是为了**稳定 softmax 的输入方差**，防止梯度消失。

### 原理推导

假设 Q、K 的每一维独立同分布，均值为 0，方差为 1：

```
Q · K = Σ(Q_i · K_i)，i 从 1 到 d_k
```

由于 Q_i 和 K_i 独立，`Q_i · K_i` 的方差 = `Var(Q_i) · Var(K_i) = 1 × 1 = 1`。

d_k 个独立项求和，方差为 `d_k`，标准差为 `√d_k`。

**问题**：当 d_k 较大时（如 64），Q·K 的数值范围很大，softmax 的输入方差很大。

**softmax 的梯度特性**：当输入差异很大时，softmax 输出趋近于 one-hot（一个 1，其余 0），此时梯度趋近于 0 → **梯度消失**。

**解决方案**：除以 √d_k，使 QK^T 的方差回到 1 附近，softmax 的输入保持在"有效区域"。

### 代码验证（`code/attention_single_head.py`）

```python
# 不缩放
scores_raw = np.dot(Q, K.T)
print(f"不缩放: scores.std() = {scores_raw.std():.3f}")  # ~8.5

# 缩放后
scores_scaled = np.dot(Q, K.T) / np.sqrt(d_k)
print(f"缩放后: scores.std() = {scores_scaled.std():.3f}")  # ~1.1

# softmax 后的权重
weights_raw = softmax(scores_raw)
weights_scaled = softmax(scores_scaled)
print(f"不缩放: 最大权重 = {weights_raw.max():.3f}")  # 0.998 (几乎 one-hot)
print(f"缩放后: 最大权重 = {weights_scaled.max():.3f}")  # 0.45  (分布更均匀)
```

**实测结果**：d_k=8 时，不缩放的 scores 标准差 ~8.5，缩放后 ~1.1。不缩放的 softmax 输出接近 one-hot，缩放后分布更合理。

### 延伸：如果除以 2 或 8 会怎样？

| 缩放因子 | scores.std() | 最大权重 | 效果 |
|---------|-------------|---------|------|
| 无缩放 | 8.5 | 0.998 | 过度集中，梯度消失 |
| ÷2 | 4.2 | 0.97 | 仍然过度集中 |
| **÷√d_k (≈2.8)** | **1.1** | **0.45** | **合理分布** |
| ÷8 | 1.1 | 0.45 | 效果类似 √d_k（d_k=8 时） |

**结论**：√d_k 不是唯一的"可用"缩放因子，但它是理论上最自然的（使方差归一化到 1）。

## Q2：多头注意力比单头注意力好在哪里？

**答：** 多头注意力让模型能**在不同子空间同时学习不同的注意力模式**，提升表达力。

### 核心机制

单头注意力：所有信息通过一组 Q、K、V 投影，学到一种注意力模式。

多头注意力：h 个头各自有独立的 W_Q^i, W_K^i, W_V^i，把 d_model 维输入投到 h 个 d_k 维子空间，每个子空间独立计算注意力。

```
MultiHead(Q, K, V) = Concat(head_1, ..., head_h) · W_O
head_i = Attention(QW_i^Q, KW_i^K, VW_i^V)
```

### 代码验证（`code/attention_multi_head.py`）

用"聚类 + 位置编码"构造结构化输入（4 个聚类 × 2 个 token），用 4 个头（d_k=16），观察到**4 种不同的注意力模式**：

| 头 | 均匀度 | 对角线权重 | 最关注的 key | 模式类型 |
|---|-------|-----------|-------------|---------|
| Head 1 | 中等 | 0.243 | A1, A1, A0, C5, C4, C4, C5, C5 | **同聚类关注**（A0→A1, C5→C4） |
| Head 2 | 41.87% | 0.024 | C4, C4, C4, C4, A1, A1, A0, A0 | **跨聚类关注**（A/B→C4, C/D→A0） |
| Head 3 | 22.28% | 0.000 | B2, B2, A1, A1, D7, D7, B3, B3 | **配对模式**（最集中） |
| Head 4 | 41.61% | 0.124 | A1, A1, A0, C5, B3, B3, C5, C5 | **混合模式** |

**关键发现**：
- Head 1 倾向于关注同一聚类的 token（语义相似）
- Head 2 倾向于关注不同聚类的 token（语义相远）
- Head 3 高度集中，关注特定配对（可能是位置相关的模式）
- 4 个头的模式**互不相同**

### 与单头的对比

如果只用单头（d_k=64），模型只能学到一种注意力模式。多头通过"并行子空间"，用几乎相同的计算量（h 个 d_k 维 vs 1 个 h·d_k 维，矩阵乘的总元素数相同）学到了 h 种不同的模式。

### 注意：这是"初始化差异"而非"训练结果"

本实验中，不同模式来自**不同随机种子的初始化**，而非训练。在真实训练中：
- 反向传播会**强化**有意义的模式（有用的头被保留，无用的头可能退化）
- 存在"头塌缩"现象：某些头可能学成一样（论文外的研究发现约 10-20% 的头可以被移除而不显著影响性能）

## Q3：为什么用 sin/cos 位置编码而不是可学习的位置编码？

**答：** sin/cos 位置编码有三个关键优势：**平移性质**、**外推能力**、**无参数**。

### 1. 平移性质（最重要）

sin/cos 编码具有性质：`PE(pos + k) = PE(pos) · M_k`（M_k 是某个旋转矩阵）

这意味着：
- 模型可以通过"相对位置"（pos + k - pos = k）来表达位置关系
- 不需要记住"绝对位置 5"是什么，只需要记住"位置 5 相对于位置 3 是 +2"

**代码验证**：

```python
# 位置 3 和位置 5 的编码差异
pe_3 = positional_encoding(4, 64)[3]
pe_5 = positional_encoding(4, 64)[5]

# 它们的差是固定的（与绝对位置无关）
diff = pe_5 - pe_3  # 只取决于 5-3=2，不取决于 3 和 5 本身

# 对比：位置 10 和位置 12 的编码差异
pe_10 = positional_encoding(11, 64)[10]
pe_12 = positional_encoding(13, 64)[12]
diff2 = pe_12 - pe_10
print(np.allclose(diff, diff2))  # True（近似相等）
```

### 2. 外推能力

可学习位置编码只能学到训练时见过的位置（如 0-512），遇到 513 时不知道用哪个 embedding。

sin/cos 编码是**公式生成的**，任何位置都能算出来：
- 训练用 0-512，推理用 513-1024 也能工作（虽然效果可能下降）

### 3. 无参数

sin/cos 编码是固定公式，不增加模型参数量。可学习编码需要额外的 embedding 表（seq_len × d_model 参数）。

### 那为什么现在（2020+）很多模型用可学习位置编码？

因为：
- **实际任务中序列长度固定**（如 BERT 用 512，不需要外推）
- **可学习编码更灵活**，能学到任务特定的位置模式
- **ALiBi、RoPE** 等 newer 方法结合了两者优点

## Q4：Transformer 的 Encoder 和 Decoder 有什么区别？

**答：** 核心区别在于**能看到什么信息**和**用途不同**。

### 结构对比

| 组件 | Encoder | Decoder |
|------|---------|---------|
| 输入 | 源句子 X 的 embedding | 目标句子 Y 的 embedding（shifted right） |
| Self-Attention | 完整的 Self-Attention | **Masked** Self-Attention（看不到未来） |
| Cross-Attention | 无 | 有（Q 来自 Decoder，K/V 来自 Encoder） |
| 层数 | n=6 | n=6 |
| 输出 | 编码表示 | 预测下一个 token 的概率 |

### 为什么 Decoder 需要 Mask？

Decoder 是**自回归**的：预测第 t 个 token 时，只能看前 t-1 个 token，不能偷看第 t 个及之后的。

如果不加 mask，训练时模型能看到整个目标句子的未来 token，"作弊"了，推理时就不行。

```
训练时（无 mask）：能看所有位置 → 泄露未来信息 → 不合法
训练时（有 mask）：只看过去位置 → 与推理一致 → ✅
```

### 代码验证：mask 的实现

```python
# 生成上三角 mask（1 表示被遮蔽）
seq_len = 4
mask = np.triu(np.ones((seq_len, seq_len)), k=1)  # 上三角为 1

# 应用到 scores
scores = np.array([[1, 2, 3, 4],
                   [2, 3, 4, 5],
                   [3, 4, 5, 6],
                   [4, 5, 6, 7]])

masked_scores = scores + (1 - mask) * (-1e9)
weights = softmax(masked_scores)

print(weights)
# [[0.9997, 0.0003, 0, 0],       # query 0 只看 key 0
#  [0.2689, 0.7311, 0, 0],       # query 1 看 key 0, 1
#  [0.0900, 0.2447, 0.6653, 0],  # query 2 看 key 0, 1, 2
#  [0.0321, 0.0871, 0.2318, 0.649]]  # query 3 看全部
```

### Cross-Attention 的作用

Decoder 的 Cross-Attention 让目标句子的每个位置都能"查询"源句子的所有位置：

```
Q = Decoder 的输出 · W_Q   (目标句子的 query)
K = Encoder 的输出 · W_K   (源句子的 key)
V = Encoder 的输出 · W_V   (源句子的 value)

CrossAttention = softmax(QK^T / √d_k) · V
```

**用途**：翻译时，"苹果"的翻译可能需要看源句的 "apple"，Cross-Attention 就是这个对齐机制。

### Encoder-only vs Decoder-only 的后续发展

| 模型 | 架构 | 任务 | 代表 |
|------|------|------|------|
| BERT | Encoder-only | 理解（分类、检索） | BERT, RoBERTa |
| GPT | Decoder-only | 生成（写作、对话） | GPT-2/3, LLaMA |
| 原始 Transformer | Encoder-Decoder | 翻译 | NMT, T5 |

## Q5：Decoder 中的 Masked Self-Attention 是怎么工作的？

**答：** 通过**上三角 mask** 把未来位置的注意力权重压到 0，保证自回归性质。

### 实现细节

**Step 1：生成 mask 矩阵**

```python
# mask[i][j] = 1 表示 query i 不能看 key j
# 只有 j <= i 的位置是可见的（下三角）
mask = np.triu(np.ones((seq_len, seq_len)), k=1)  # 上三角为 1
```

**Step 2：应用到 scores**

```python
# 被遮蔽的位置加上极大负数
masked_scores = scores + (1 - mask) * (-1e9)
# mask=1 → +(-1e9) → softmax 后趋近 0
# mask=0 → +0 → 正常 softmax
```

**Step 3：softmax 后，被遮蔽位置的权重趋近 0**

```
scores: [[1, 2, 3, 4]]
masked: [[1, -1e9, -1e9, -1e9]]  # 只有第一个位置可见
weights: [[1.0, 0.0, 0.0, 0.0]]  # softmax 后完全集中在第一个位置
```

### 为什么用 -1e9 而不是 -inf？

- `-inf` 会导致 `exp(-inf) = 0`，但 `(0/0)` 在 softmax 中可能产生 NaN（当一行全是 -inf 时）
- `-1e9` 足够大（exp(-1e9) ≈ 0），但不会导致浮点溢出
- PyTorch 的 `F.softmax` 内部也用了类似技巧

### 训练和推理的一致性

| 阶段 | 能看到什么 | 实现方式 |
|------|-----------|---------|
| 训练 | 每个位置只能看自己的过去 | mask |
| 推理 | 逐 token 生成，天然只看过去 | 不需要 mask（但实现中通常保留） |

训练时用 mask 确保"不泄露未来信息"，推理时因为是逐 token 生成，不需要 mask（但如果用 KV cache 等优化，mask 逻辑仍在）。

## Q6：Cross-Attention 在 Decoder 中有什么作用？

**答：** Cross-Attention 是 **Encoder 和 Decoder 之间的信息桥梁**，让 Decoder 的每个位置都能"查询"Encoder 的输出。

### 具体机制

```
Decoder Cross-Attention 的输入：
  Q ← Decoder 上一层的输出（目标句子的表示）
  K ← Encoder 最终输出（源句子的表示）
  V ← Encoder 最终输出（源句子的表示）

CrossAttention = softmax(Q · K^T / √d_k) · V
```

**直觉**：目标句子的每个位置（query）都在问源句子的所有位置（key）"你跟我有什么关系？"，然后根据相关性加权求和源句子的内容（value）。

### 在翻译中的角色

以翻译 "I love apples" → "J'aime les pommes" 为例：

```
当 Decoder 生成 "J'aime" 时：
  Cross-Attention 可能对齐到 "I love"（主语+动词）

当 Decoder 生成 "pommes" 时：
  Cross-Attention 可能对齐到 "apples"（名词对名词）
```

**这就是"注意力对齐"（attention alignment）**：可以可视化 Cross-Attention 的权重矩阵，看到源句和目标句的单词对应关系。

### 与 Self-Attention 的对比

| 类型 | Q 来源 | K, V 来源 | 作用 |
|------|--------|----------|------|
| Self-Attention (Encoder) | X | X | 源句子内部的信息融合 |
| Self-Attention (Decoder, Masked) | Y | Y | 目标句子内部的信息融合（只看过去） |
| **Cross-Attention (Decoder)** | **Y** | **Encoder 输出** | **跨句子对齐** |

### 注意：不是所有 Transformer 都需要 Cross-Attention

- **BERT（Encoder-only）**：没有 Decoder，不需要 Cross-Attention
- **GPT（Decoder-only）**：没有 Encoder，不需要 Cross-Attention
- **原始 Transformer（Encoder-Decoder）**：需要 Cross-Attention 来对齐源句和目标句
- **ViT**：只有 Encoder，不需要 Cross-Attention

## Q7：为什么要用残差连接和 Layer Normalization？

**答：** 残差连接解决**梯度消失**，LayerNorm 解决**数值稳定**，两者配合让深层网络可训练。

### 残差连接（Residual Connection）

**问题**：深层网络中，梯度需要逐层回传。如果每层的变换是 `f(x)`，梯度是 `∂L/∂x = ∂L/∂f · f'(x)`。当层数多时，`f'(x)` 连乘多次会趋近 0（梯度消失）。

**解决方案**：残差连接 `y = x + f(x)`，梯度变为 `∂L/∂x = ∂L/∂y · (1 + f'(x))`。即使 `f'(x) → 0`，梯度仍有 `∂L/∂y · 1` 的"快捷通道"。

```python
# 无残差
h = LayerNorm(Attention(x))  # 梯度经过 Attention 和 LayerNorm 的连乘
# 有残差
h = x + LayerNorm(Attention(x))  # 梯度有一条"直接回传"的路径
```

### Layer Normalization

**问题**：深层网络中，每层的输入分布可能剧烈变化（如某些层输出全正，某些层输出全负），导致后续层的训练不稳定。

**解决方案**：对每个 token 的 d_model 维特征做标准化：

```python
# 对每个 token，计算均值和标准差，然后标准化
mean = x.mean(axis=-1, keepdims=True)  # (batch, seq, 1)
var = x.var(axis=-1, keepdims=True)     # (batch, seq, 1)
x_norm = (x - mean) / np.sqrt(var + eps)  # 标准化

# 然后可学习的 scale 和 shift
y = gamma * x_norm + beta  # gamma, beta 是可学习参数
```

**为什么是 Layer 而不是 Batch？**
- BatchNorm 对 batch 维度求统计，依赖 batch size（推理时不稳定）
- LayerNorm 对特征维度求统计，与 batch size 无关（RNN/Transformer 更适合）
- Transformer 的序列长度可变，BatchNorm 的"batch"语义不清晰

### 两者的配合顺序（Post-LN vs Pre-LN）

**原始 Transformer（Post-LN）**：
```
y = LayerNorm(x + Sublayer(x))
```

**现代实现（Pre-LN）**：
```
y = x + Sublayer(LayerNorm(x))
```

**区别**：
| | Post-LN | Pre-LN |
|---|---------|--------|
| 梯度流 | 经过 LayerNorm 的"压缩"，可能不稳定 | 有残差的快捷通道，梯度更稳定 |
| 训练稳定性 | 需要 warmup 学习率 | 不需要 warmup |
| 最终性能 | 可能略好（但需要更小心调参） | 略低但更稳定 |

### 代码中的体现

在 `code/transformer_diagram.py` 绘制的结构图中，每个子层（Attention、FFN）都有：
```
输入 → Sublayer → 残差连接 → LayerNorm → 输出
```

## Q8：ViT（Vision Transformer）和原始 Transformer 有什么区别？

**答：** ViT 去掉了 Decoder，只用 Encoder，并用**图像 patch** 替代文本 token。

### 核心区别

| 组件 | 原始 Transformer | ViT |
|------|----------------|-----|
| 输入 | 文本 token 的 embedding | 图像 patch 的 embedding |
| 架构 | Encoder + Decoder | **只有 Encoder** |
| 位置编码 | sin/cos 绝对位置编码 | 可学习位置编码 |
| 目标 | 翻译（序列到序列） | 图像分类（分类任务） |
| 输出 | 下一个 token 的概率 | 图像类别的概率 |

### ViT 的输入处理

**Patch Embedding**：把图像切成固定大小的 patch（如 16×16），每个 patch 用线性层映射到 d_model 维向量。

```
输入图像: 224 × 224 × 3
切成 patch: (224/16)² = 196 个 patch，每个 16×16×3 = 768 维
线性投影: 768 → d_model (如 768)
加上 [CLS] token: 197 个 token
加上位置编码: 每个 token + 对应位置的编码
```

**[CLS] token**：类似 BERT 的 [CLS]，是一个特殊 token，用于聚合全局信息。分类任务用 [CLS] 的输出做分类。

### 为什么 ViT 效果好？

1. **全局感受野**：CNN 的感受野随层数逐渐扩大，而 Transformer 的自注意力一步就能看全局
2. **数据规模化**：在大规模数据集（JFT-300M）上预训练，ViT 效果超过 ResNet
3. **架构灵活性**：Transformer 天然适合序列建模，图像 patch 序列也是序列

### 为什么 ViT 没有 Decoder？

图像分类是"理解"任务（输入一张图，输出一个类别），不需要"生成"新序列。
- 翻译任务需要 Decoder 来逐步生成目标句子
- 分类任务只需要 Encoder 来提取全局特征

### 后续发展：Decoder-only 的视觉模型

虽然 ViT 是 Encoder-only，但后来的视觉模型也用了 Decoder-only：
- **CLIP**：Encoder + 对比学习
- **Swin Transformer**：Encoder-only，但用滑动窗口注意力
- **DALL-E 2 / Stable Diffusion**：用了类似 Decoder 的架构做图像生成

### 代码验证（`code/transformer_diagram.py`）

在 fig03_vit_structure.png 中绘制了 ViT 的完整流程：
```
图像 → 切 patch → Patch Embedding → [CLS] token → 位置编码 → Encoder 层堆叠 → [CLS] 输出 → 分类头
```

## 总结

| 问题 | 核心答案 |
|------|---------|
| Q1: 为什么除以 √d_k？ | 稳定 softmax 输入方差，防止梯度消失 |
| Q2: 多头 vs 单头？ | 在不同子空间学习不同模式，提升表达力 |
| Q3: sin/cos vs 可学习位置编码？ | 平移性质、外推能力、无参数 |
| Q4: Encoder vs Decoder？ | Encoder 看全局，Decoder 看过去+对齐源句 |

| Q7: 残差 + LayerNorm？ | 残差解决梯度消失，LayerNorm 解决数值稳定 |
| Q8: ViT vs Transformer？ | ViT 去 Decoder 用 Encoder，图像 patch 替代文本 token |
