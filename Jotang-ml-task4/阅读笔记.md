## 二、理解过程（从迷茫到理解）

### 阶段 1：读完论文，只记住公式

第一次读论文，我只记住了：
- `Attention(Q, K, V) = softmax(QK^T / √d_k) · V`
- "多头"是并行几个这样的计算
- 有残差连接和 LayerNorm

但完全不理解：**为什么要除以 √d_k？为什么要多头？Q、K、V 到底是什么？**

### 阶段 2：看可视化教程，理解直觉

看完 3Blue1Brown 视频后，建立了核心直觉：

| 概念 | 类比 |
|------|------|
| Q (Query) | 你提出的问题 |
| K (Key) | 数据库里的索引标签 |
| V (Value) | 数据库里的实际内容 |
| Q·K | 问题与标签的匹配度 |
| softmax(Q·K) | 匹配度归一化为权重 |
| 权重·V | 按权重加权求和内容 |

**关键洞察**：Attention 不是新运算，而是**可微的加权求和**。权重由 Q 和 K 的相似度决定。

### 阶段 3：手写代码，遇到真实问题

开始手写单头注意力时，遇到了几个实际问题：

1. **为什么要除以 √d_k？**
   - 第一次写的时候忘了除，热力图看起来"太黑"（所有权重集中在一个点）
   - 查资料后发现：Q·K 的方差随 d_k 线性增长，除以 √d_k 稳定方差
   - 代码验证：`scores.std()` 从 ~8 降到 ~1.2

2. **多头到底怎么拆分？**
   - 论文说"把 d_model 分成 h 份"，但具体怎么 reshape？
   - 参考 Annotated Transformer，搞清了 `(batch, seq, d_model)` → `(batch, seq, h, d_k)` → `(batch, h, seq, d_k)` 的形状变换
   - 用 `reshape` + `transpose` 实现

3. **位置编码为什么用 sin/cos？**
   - 一开始不理解为什么不用可学习的
   - 读了论文 Section 3.5 才明白：sin/cos 编码具有平移性质，`PE(pos+k)` 可以表示为 `PE(pos)` 的线性函数
   - 这意味着模型可以外推到训练时没见过的序列长度

### 阶段 4：理解 ViT，完成架构对比

读 ViT 论文时发现了一个有趣的事实：**ViT 去掉了论文的 Decoder，只用 Encoder**。

这让我重新理解了 Transformer 的两种变体：
- **Encoder-only**（BERT、ViT）：理解任务（分类、检索）
- **Decoder-only**（GPT）：生成任务（写作、对话）
- **Encoder-Decoder**（原始 Transformer）：翻译任务（需要理解+生成）

## 三、遇到的难点

### 难点 1：Q、K、V 的来源混淆

**问题**：论文里 Q、K、V 到底从哪来？是输入的 embedding 吗？

**困惑过程**：
- 一开始以为 Q=K=V=输入 embedding
- 后来发现还有 W_Q、W_K、W_V 投影
- 更困惑的是 Decoder 里的 Cross-Attention，K、V 来自 Encoder 的输出

**最终理解**：

| 场景 | Q 来源 | K 来源 | V 来源 |
|------|--------|--------|--------|
| Encoder Self-Attention | X·W_Q | X·W_K | X·W_V |
| Decoder Self-Attention (Masked) | Y·W_Q | Y·W_K | Y·W_V |
| Decoder Cross-Attention | Y·W_Q | Encoder输出·W_K | Encoder输出·W_V |

其中 X 是源句子的 embedding，Y 是目标句子的 embedding。

### 难点 2：Masked Attention 的 mask 方向

**问题**：Decoder 里的 mask 是怎么实现的？为什么是上三角？

**困惑过程**：
- 一开始以为 mask 是下三角（因为"看不到未来"）
- 后来发现：mask 矩阵是上三角为 1（被 mask 的位置），因为 query i 不能看到 key j（j > i）

**最终理解**：
```
mask[i][j] = 0 if j <= i else 1  # 1 表示被遮蔽
scores + (1 - mask) * (-1e9)     # 把被遮蔽的位置变成极大负数
```
这样 softmax 后，被遮蔽位置的权重趋近于 0。

### 难点 3：残差连接和 LayerNorm 的顺序

**问题**：残差连接和 LayerNorm 到底是先谁后谁？

**困惑过程**：
- 论文原图是：残差 → LayerNorm → Sublayer
- 但后来的实践（如 Pre-LN Transformer）发现：LayerNorm → Sublayer → 残差更稳定

**最终理解**：
- 原始 Transformer 用的是 **Post-LN**：`x + Sublayer(LayerNorm(x))`
- 现代实现（GPT、BERT）多用 **Pre-LN**：`x + Sublayer(LayerNorm(x))` 或 `LayerNorm(x + Sublayer(x))`
- 两种都可以，但 Pre-LN 训练更稳定，不需要学习率 warmup

### 难点 4：多头注意力的等价性

**问题**：论文里说"多头注意力等于一个更大的注意力"，这是真的吗？

**最终理解**：
- 数学上等价：h 个头 × d_k 维 = 1 个头 × (h × d_k) 维
- 但计算量不同：多头是 h 个并行的 (d_k × d_k) 矩阵乘，单头是 1 个 (d_model × d_model) 矩阵乘
- **关键区别**：多头让每个头有独立的参数，可以在不同子空间学习不同的模式
  - 实验证据（本任务 `attention_multi_head.py`）：
    - Head 1：关注同一聚类的 token（自聚类模式）
    - Head 2：关注不同聚类的 token（交叉聚类模式）
    - Head 3：高度集中，关注特定配对（最尖锐的模式）
    - Head 4：混合模式
  - 这说明多头确实能学到不同的注意力模式

## 四、代码实践中的发现

### 发现 1：手写实现与 PyTorch 的精度差异

**现象**：
- 单头注意力：手写 NumPy vs PyTorch，最大差异 ~2.87e-07
- 多头注意力：手写 NumPy vs PyTorch，最大差异 ~2.70e-06

**原因分析**：
1. **float64 vs float32**：NumPy 默认 float64，PyTorch 默认 float32
2. **计算顺序**：PyTorch 内部可能使用融合操作（如 `softmax + matmul` 融合），浮点累加顺序不同
3. **数值稳定性**：PyTorch 的 softmax 实现了 `x - max(x)` 的优化，我的手写实现也加了，但可能还有其他细节差异

**结论**：差异在 1e-6 量级，属于浮点精度范围，实现是正确的。

### 发现 2：随机权重下注意力接近均匀分布

**现象**：第一次写多头注意力时，所有头的权重都接近均匀分布（1/seq_len）。

**原因分析**：
- 随机投影 + 随机输入 → Q·K 的 scores 近似 N(0, σ²)
- softmax 对近似均匀的 scores 输出近似均匀的权重
- **要看到有意义的注意力模式，需要**：
  1. 有结构的输入（如聚类、位置编码）
  2. 经过训练（反向传播会强化有意义的模式）

**解决方案**：在演示中用"聚类 + 位置编码"构造有结构的输入，并用不同种子初始化各头的权重，成功展示了 4 种不同的注意力模式。

### 发现 3：np.dot 和 np.matmul 在 3D 数组上的差异

**踩坑**：`np.dot` 对 3D 数组的行为不符合直觉。

```python
# 错误：np.dot 对 (batch, seq, d) 数组做"批量矩阵乘"
scores = np.dot(Q, K.transpose(0, 2, 1))  # 结果不对！

# 正确：np.matmul 是真正的批量矩阵乘
scores = np.matmul(Q, np.swapaxes(K, -1, -2))  # ✅
```

**根因**：
- `np.dot` 对 3D 数组：`dot(A, B)` = `sum(A[..., :, k] * B[..., k, :], axis=-1)`（最后一维收缩）
- `np.matmul` 对 3D 数组：先 reshape 成 2D，做矩阵乘，再 reshape 回来
- 对于注意力计算，我们需要的是 `(batch, seq, d) × (batch, d, seq) = (batch, seq, seq)`，这是 matmul 的语义

**教训**：处理 batch 维度的矩阵运算时，**永远用 `np.matmul`**，不要用 `np.dot`。

## 五、遗留疑问

### 疑问 1：为什么 √d_k 是最优缩放因子？

论文说除以 √d_k 可以稳定方差，但我没验证过：
- 如果 d_k = 16，√d_k ≈ 4
- 如果除以 2 或 8 会怎样？
- 有没有理论证明 √d_k 是最优的？

**猜想**：对于 Q、K 的每个分量独立同分布 N(0, 1/d_k)，Q·K = Σ(Q_i · K_i)，方差 = d_k × (1/d_k)² = 1/d_k。除以 √d_k 后方差 = 1/(d_k × d_k) = 1/d_k²... 等等，这好像不对。需要重新推导。

### 疑问 2：位置编码的"外推"能力到底如何？

论文说 sin/cos 位置编码可以外推到训练时没见过的长度。但实际实验中：
- 如果训练时用 0-512 的位置，推理时用 513-1024 会怎样？
- 有没有人在实际任务中验证过这个外推能力？

**后续计划**：找一下 "Learning to Extrapolate" 相关的论文（如 ALiBi、Relative Position Bias）。

### 疑问 3：多头注意力的"不同模式"是训练出来的还是天生的？

在我的演示中，用不同随机种子初始化各头，就得到了不同的注意力模式。但在实际训练中：
- 初始的随机差异会被保留还是被抹平？
- 有没有"头塌缩"（head collapse）的问题？
- 多头注意力有没有可能退化成单头（所有头学一样的东西）？

**后续计划**：看一些关于 "attention head analysis" 的论文（如 "Are Sixteen Heads Really Better than One?"）。

### 疑问 4：ViT 的 patch 大小怎么选？

ViT 论文里用了 16×16 的 patch，但：
- 为什么是 16？8 或 32 会怎样？
- patch 太小 → token 太多 → 计算量爆炸
- patch 太大 → 丢失细节信息

**猜想**：这是一个经验值，需要在具体任务上 grid search。

### 疑问 5：Transformer 的自注意力复杂度是 O(n²)，有什么优化方案？

论文提到这个复杂度，但没有解决。实际应用中：
- **Flash Attention**：利用 GPU 的 SRAM 优化显存访问，不减少计算量但大幅加速
- **Linear Attention**：用近似方法把 O(n²) 降到 O(n)，但精度可能下降
- **Sparse Attention**：只关注局部窗口或特定位置

**后续计划**：了解 Flash Attention 的原理（它是怎么在不改变结果的情况下加速的）。

## 六、总结

### 核心收获

1. **Attention 的本质**：可微的加权求和，权重由 Q·K 的相似度决定
2. **多头的意义**：在不同子空间学习不同的模式，提升模型表达力
3. **位置编码**：sin/cos 编码具有平移不变性，支持序列长度外推
4. **架构灵活性**：Transformer 可以只用 Encoder（BERT/ViT）、只用 Decoder（GPT）、或两者都用（原始 Transformer）

### 代码能力

1. 能手写 Scaled Dot-Product Attention（单头 + 多头）
2. 能画出 Transformer 的完整结构图
3. 能分析注意力热力图，理解模型在"关注什么"
4. 能与 PyTorch 官方实现对比验证

### 待提升

1. 对数学推导（如 √d_k 的最优性）还不够深入
2. 对工业级优化的了解（Flash Attention、混合精度等）还不够
3. 对后续发展（BERT、GPT、ViT、DeiT 等）的理解还不够系统
