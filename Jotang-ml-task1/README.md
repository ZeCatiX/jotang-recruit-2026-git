| 项 | 值 |
|---|---|
| Python | 3.13.9（Anaconda） |
| PyTorch | 2.11.0+cpu |
| scikit-learn | 1.7.2 |
| numpy | 2.3.5 |
| matplotlib | 3.10.6 |
| 显卡 | RTX 5060 Laptop（8 GB），**但 torch 是 CPU 版，`torch.cuda.is_available() = False`** |
| 中文图表 | 需要 `Noto Sans SC`（Windows 自带，路径 `C:\Windows\Fonts\Noto Sans SC.ttf`） |

安装：

```bash
pip install torch scikit-learn numpy matplotlib
```

**两个环境相关的坑，先记下来：**

1. **`torch.manual_seed_all()` 在 2.11.0 已经不存在了**，直接调用会 `AttributeError`。
   现在的 `torch.manual_seed()` 内部已经会给所有设备播种，不需要再单独调。
   `common.py` 里用 `hasattr` 做了兼容：

   ```python
   torch.manual_seed(seed)
   if hasattr(torch, "manual_seed_all"):   # 老版本还有这个接口
       torch.manual_seed_all(seed)
   ```

2. **CPU 版 PyTorch 没有显存可查**。`torch.cuda.memory_allocated()` 不可用，
   所以 `common.py::process_rss_mib()` 改用 Windows 的
   `psapi.GetProcessMemoryInfo()` 读进程常驻内存（WorkingSetSize）当替代指标。
   纯 ctypes 实现，不依赖 psutil。
   注意调用 `GetCurrentProcess` 前必须显式声明 `restype = c_void_p`，
   否则 ctypes 默认按 32 位 `c_int` 截断 64 位句柄，后面的调用会**静默失败**返回 `nan`。

## 运行方法

两条命令，顺序执行：

```bash
python task1_main.py     # 任务 1/2/3/5，约 30 秒
python experiments.py    # 任务 4，约 90 秒（35 次训练）
```

产物会自动写到 `figures/` 和 `results/`，控制台会打印每一步的指标。

想只跑一个变量的对照实验，直接改 `experiments.py` 顶部的 `ABLATIONS` 列表。

## 关键结果速览

**主模型**（2 隐藏层 × 64，ReLU，Adam lr=1e-3，batch 32，150 epoch）：

| 数据集 | 样本数 | 准确率 | 平均损失 |
|---|---|---|---|
| 训练集 | 210 | 0.9952 | 0.0320 |
| 验证集 | 45 | 0.9556 | 0.2124 |
| 测试集 | 45 | 1.0000 | 0.0000 |

模型保存 20.8 KB，加载后在测试集上的预测与原模型**逐条完全一致**
（`np.array_equal` 断言通过）。

**对照实验最反直觉的三个发现**（完整结论见 `results/实验表格.md`）：

1. 宽度 32/64/128/256 的测试准确率全是 1.000，看起来完全一样，
   但**验证损失从 0.2124 一路涨到 0.3850**——更宽的网络泛化余量更小。
   参数量 ×189（354 → 67,074），换来的是负收益。
2. 学习率 1e-2 的测试准确率照样 1.000，但验证损失冲到 0.4107，
   是甜点 3e-4（0.1521）的 2.7 倍。只看准确率会漏掉「学习率过大」这种失败模式。
3. 数据噪声是唯一能让结果大幅下滑的变量：噪声 0.0→0.8，
   测试准确率 100.0% → 75.6%，而前面六个变量最多只影响 ±3 个百分点。

**不均衡实验**（90/10，正类和负类分布大面积重叠）：

| 方案 | 总准确率 | 正类召回 | 正类F1 |
|---|---|---|---|
| 平凡基线：全猜多数类 | 0.900 | 0.000 | 0.000 |
| 直接训练（不加权） | 0.947 | 0.467 | 0.636 |
| 加权训练（正类 5.0×） | 0.920 | 0.733 | 0.647 |

准确率说「不加权更好」（0.947 > 0.920），F1 说「加权更好」（0.647 > 0.636）——
这就是为什么类别不均衡时**不能只看准确率**。

**过拟合实验**（60 条数据，噪声 0.6，36 条训练）：

| 配置 | 训练 | 验证 | 差距 | 测试 | 参数 |
|---|---|---|---|---|---|
| 1 层 × 16 | 0.833 | 0.750 | +0.083 | 0.667 | 82 |
| 2 层 × 64 | 0.889 | 0.667 | +0.222 | 0.667 | 4,482 |
| 4 层 × 256，无正则 | 0.944 | 0.667 | **+0.278** | 0.667 | 198,658 |
| 4 层 × 256 + dropout 0.2 + wd 1e-2 | 0.861 | 0.750 | +0.111 | 0.667 | 198,658 |

差距随容量单调变宽（+0.083 → +0.222 → +0.278），加正则压回 +0.111，
而四个模型的测试准确率全是 0.667——**单看准确率根本看不出过拟合**。

## 可复现性

所有实验共用同一个随机种子 `SEED = 0`（`common.py` 顶部），
`setup_seeds()` 同时固定 `random` / `numpy` / `torch`，
每次训练前都会重新调用一次。

数据生成（`make_moons`）、分层划分（`train_test_split`）、
模型权重初始化、mini-batch 采样全部走这个种子，
所以两次运行（甚至换机器重装环境）得到的准确率应该**完全一致**。

注意训练**耗时**不具备可复现性，它会随机器负载波动，
不同次运行差个 20~40% 很正常，对比实验里看相对趋势就行。

## 已知局限（主动说明，不藏）

1. **内存数据不是显存**。本机 torch 是 CPU 版，`rss_delta` 反映的是
   进程常驻内存增量。数据只有 300×2 个浮点数，增量都在 ±3 MiB 以内，
   主要反映分配器行为，**不能当作显存的精确测量**。
   `experiments.py` 因此在正式实验前先跑了一次预热，
   避免分配器的一次性开销把「宽度 16 反而占 70 MiB」这种假象混进表格。
2. **验证集和测试集只有 45 条**，准确率的最小分辨率是 1/45 ≈ 2.2 个百分点，
   所以很多配置的测试准确率都撞到 1.000 的天花板。
   这也是对照实验里我转而用**验证损失**和**训练耗时**下判断的原因。
3. **`torch.manual_seed_all` 在 2.11.0 被移除**，代码用 `hasattr` 兼容旧版本，
   但如果换到很老的 PyTorch（1.x），`train_model` 里的一些写法可能还要调整。
4. 决策边界用 `contourf` 画的是**在特征平面密集采样后**的模型预测，
   不是模型的解析边界。400×400 的网格采样，视觉上够用了。
